版本：QC\_EQUIPMENT\_ATTRIBUTE\_SCORE\_V1\_3。日期：2026-11-02。状态：正式评分规则提案，替代此前“70%—100%纯随机评分”方案。装备评分最高100,000,000分，评分来源为属性数量、每条属性上限及当前有效属性值。

## 1. 设计目标

装备评分不是独立随机数，也不是装备品质的简单换算。它反映一件装备的属性槽填充程度，以及每条属性当前数值相对自身合法上限的完成度。

评分必须回答：

- 装备有多少条有效属性？
- 每条属性在当前装备等级、品质、部位和词条档位下，最高可以达到多少？
- 当前属性实际达到该上限的百分之多少？
- 洗炼替换其中一条属性后，整件装备评分会上升还是下降？

评分只用于装备比较、排序、收藏和洗炼预览；不增加HP、ATK、DEF，不参与Pcomposite、伤害、掉落、PVP或标准宠物积分赛结算。

## 2. 评分对象与属性数量

首期评分对象是防具上的洗炼属性/普通词条/战术铭纹槽，不把基础HP、ATK、DEF面板值重复当作额外词条槽计分。

- 每件防具最多3条评分属性，Nmax=3。
- 当前有效评分属性数量为N，空槽不计入N。
- 金装第三槽若由战术铭纹替换普通词条，仍然只算一条属性。
- 不允许把同一条属性的名称、数值和百分比重复计成三条。
- 武器沿用独立规则：V2明确武器不新增随机词条槽。武器评分以其现有可评分属性条目为准；若武器没有随机属性槽，则不虚构3条词条。武器首期仅显示“武器基础评价/待配置”，待武器属性评分口径单独配置后再开放统一分数，不能套用防具词条槽公式。
- 未来增加装备属性槽时，必须同步修改Nmax与评分版本，不可只增加槽位却仍沿用旧分母。

## 3. 每条属性完成率

每条属性都必须在配置表中有独立上限，不能共用一个绝对数值上限。

对第i条有效属性：

Ratio\_i = clamp(CurrentValue\_i / AttributeMax\_i, 0, 1)

其中：

- CurrentValue\_i：当前实际生效的属性值，采用服务器权威值。
- AttributeMax\_i：该条属性在当前装备所属岛、有效等级Le、部位、品质、词条类型和合法档位下可达到的最大值。
- Ratio\_i：该条属性完成率，范围0%—100%。

如果属性配置直接提供完成百分比（如界面显示78%），服务器仍应使用CurrentValue/AttributeMax计算；百分比只作为UI显示，不接受客户端传来的百分比作为权威值。

属性上限读取顺序：

1. 属性ID（如F01蛮力、F04锐眼、F05暴烈或铭纹ID）。
2. 装备部位允许词池。
3. 装备品质系数与该品质档位规则。
4. 装备有效等级Le及所属岛成长。
5. 词条档位或洗炼品质。
6. 全身上限、互斥规则及实际生效裁剪。

V3已定义的蓝/紫/金词条品质系数0.40/0.64/1.00、低/中/高档位、部位词池和全身上限继续生效。F04锐眼沿用其“不乘品质系数”的例外。属性上限必须由上述规则算出，不可简单拿金色高档值套到所有品质。

## 4. 装备总评分公式

为同时体现属性条数与属性数值完成率，采用“槽位占用率 × 有效属性平均完成率”。

CountFactor = N / Nmax

ValueFactor = Σ(Weight\_i × Ratio\_i) / ΣWeight\_i

EquipmentScore = floor(100000000 × CountFactor × ValueFactor)

首期所有有效属性的Weight\_i=1，保持公平、透明、容易理解。未来若有明确的属性评分权重调整，必须升级评分版本并公布原因，不能暗中给攻击属性更高分。

防具Nmax=3，因此：

- 3条属性：数量系数100%。
- 2条属性：数量系数66.6667%。
- 1条属性：数量系数33.3333%。
- 0条属性：评分0分。

3条属性均达到各自上限时，评分为100,000,000分。两条属性即使都达到各自上限，最高也只有66,666,666分；一条属性达到上限，最高为33,333,333分。这样属性数量本身确实影响总评分。

## 5. 参考计算

以参考洗炼界面的三条当前属性为例：

| 当前属性 | 当前值/上限 | 完成率 |
| --- | --- | --- |
| 抗暴 | 当前值为该属性上限的78% | 78% |
| 暴击 | 当前值为该属性上限的74% | 74% |
| 抗暴 | 当前值为该属性上限的78% | 78% |

ValueFactor=(78%+74%+78%)/3=76.6667%

CountFactor=3/3=100%

EquipmentScore=floor(100000000×1×0.766667)=76,666,666分

洗炼候选替换其中一条：

- 若新属性完成率为84%，新完成率为(84%+74%+78%)/3=78.6667%，评分约78,666,666分，提升约2,000,000分。
- 若新属性完成率为30%，新完成率为(30%+74%+78%)/3=60.6667%，评分约60,666,666分，下降约16,000,000分。

上述示例中的78%、74%、84%、30%均为“当前值/该属性上限”的完成率演示，不代表截图中未展示的具体最大数值。

## 6. 多条同类属性与全身上限

V3允许F01—F04部分基础属性同件重复。重复属性仍然是多个属性槽，会计入属性数量N，但必须先应用V3全身属性上限，再计算评分。

处理顺序：

1. 按属性ID汇总同类属性的原始当前值。
2. 应用该属性全身上限及其他合法限制。
3. 得到最终有效总值。
4. 将有效总值按各条原始贡献比例分摊回对应槽位；原始总值为0时各槽均为0。
5. 每个槽分别除以该槽对应的合法上限，限制在0—100%。
6. 再计算属性数量系数与平均完成率。

这样避免重复属性超过全身上限后仍然刷高评分，也避免同一属性被重复计分。达到全身上限后，继续增加该属性的溢出部分不再贡献评分。

## 7. 属性数量和空槽规则

| 有效属性数量 | 数量系数 | 属性全部满上限时最高评分 |
| --- | --- | --- |
| 0条 | 0% | 0 |
| 1条 | 33.3333% | 33,333,333 |
| 2条 | 66.6667% | 66,666,666 |
| 3条 | 100% | 100,000,000 |

空槽不按0%属性加入平均值，而是通过CountFactor降低评分。不能既把空槽加入平均分又乘数量系数，避免双重惩罚。

## 8. 品质、等级与上限关系

评分不再直接乘一个独立的蓝/紫/金品质分数。品质通过AttributeMax影响属性完成率：

- 蓝装的合法词条上限按蓝色系数与蓝色档位配置计算。
- 紫装的合法词条上限按紫色系数与紫色档位配置计算。
- 金装的合法词条上限按金色系数与金色档位配置计算。
- 装备等级/岛序提高时，属性上限按对应成长数据变化。
- 当前属性值与上限同步增长且完成率不变时，评分不因单纯数值单位变大而变化。

因此蓝装满属性和金装满属性可能获得相同评分，但装备品质仍然单独展示。评分表达“自身上限完成度”，品质表达“装备等级/稀有度”，二者不混淆。

## 9. 洗炼界面交互（按参考图）

保留当前洗炼窗口结构：左侧装备图与名称，右侧“当前属性”和“洗炼结果”两列，底部替换与洗炼按钮。

新增展示：

- 装备名称下方或等级行旁显示“装备评分 76,666,666 / 100,000,000”和当前星级。
- 当前属性每一行显示属性名称、当前值、完成率和属性进度条。
- 洗炼结果每一行显示候选属性名称、候选值、相对自身上限完成率。
- 玩家选中一个候选后，系统只替换对应旧属性，另外两条保持不变，并即时计算“洗炼后评分”与“评分变化”。
- 评分提升显示“+分数”；评分下降显示“-分数”；不允许只显示颜色而隐藏具体数值。
- 若候选属性类型变化，必须读取新属性自己的AttributeMax重新计算，不能沿用旧属性上限。
- 确认替换前再次展示旧评分、新评分和差值；取消不改变当前评分与属性。

建议UI文案：<br />“当前评分：76,666,666”<br />“洗炼预览：78,666,666”<br />“评分变化：+2,000,000”<br />“每件装备最多3条评分属性；评分由属性数量及各属性上限完成率共同决定。”

## 10. 星级映射

星级只由最终评分决定，采用全局固定阈值：

| 装备评分 | 星级 |
| --- | --- |
| 0—19,999,999 | ★☆☆☆☆ |
| 20,000,000—39,999,999 | ★★☆☆☆ |
| 40,000,000—59,999,999 | ★★★☆☆ |
| 60,000,000—79,999,999 | ★★★★☆ |
| 80,000,000—100,000,000 | ★★★★★ |

品质蓝/紫/金独立展示，不等同评分星级。星级只用于装备评分展示，不替代宠物星级、装备品质或强化等级。

## 11. 服务端字段与刷新规则

每件防具实例保存或派生：

- EquipmentRatingVersion：评分版本。
- EquipmentScore：0—100,000,000整数。
- EquipmentStar：1—5星。
- AttributeCount：有效评分属性数量。
- AttributeMaxSnapshot：各属性本次计算所用上限版本/键。
- AttributeRatioList：每条属性的完成率。
- RatingBreakdown：数量系数、平均完成率、最终评分。
- PendingPreviewScore：洗炼候选预览分，只在待确认事务存在时使用。

评分由服务器根据装备实例的真实属性、属性ID、品质、岛序、有效等级与全局上限计算。客户端不得提交最终评分或属性完成率。洗炼候选生成时旧属性继续生效；确认替换后原子提交属性并重算评分；断线重连返回同一候选与同一预览结果。

强化、星铸、升品、跨岛传承若改变属性上限或当前值，必须重新计算；普通洗炼只在候选确认后重算。装备分解后新制造的实例按新属性重新评分。评分版本升级不得修改装备原始属性或重复扣费。

- [ ] 0、1、2、3条属性数量边界。
- [ ] 每种属性当前值为0%、25%、50%、75%、100%上限时的计算。
- [ ] 不同属性类型使用不同上限，不能混用绝对数值。
- [ ] 蓝/紫/金品质、低/中/高档位分别正确生成AttributeMax。
- [ ] F04锐眼品质例外正确；F01—F04重复属性与全身上限正确。
- [ ] 金装铭纹替换第三条普通词条，不增加属性数量。
- [ ] 洗炼同属性提升、跨属性替换、属性下降三类预览正确。
- [ ] 候选取消不改变旧评分；确认替换后评分与预览一致。
- [ ] 装备评分始终不超过100,000,000。
- [ ] 评分不改变战斗属性、Pcomposite、PVP或标准宠物积分赛结果。

## 13. 与既有版本的关系

本V1.3方案替代V1固定0—1000分、V1.1培养完成度评分、V1.2纯随机70%—100%评分。保留V2装备基础属性、品质成长、强化星铸、制造成本和1极约束；保留V3普通词条、铭纹、部位词池、洗炼交互和模式边界。

本规则当前针对防具洗炼属性。32把武器没有新增随机词条槽，不能强行套用防具的三属性公式；武器需按其实际可评分属性数量与属性上限建立对应配置后，才能纳入同一评分体系。

## 14. 关键口径补充：属性上限必须取最高合法档

计算Ratio时，AttributeMax必须取“同一属性类型在当前装备所属岛、有效等级、部位与品质下允许生成的最高合法档位（通常为高档）”的数值，不能取当前词条自己的低/中/高档上限。否则低档词条也会被错误计算为100%完成度，失去区分洗炼质量的意义。

例如同一属性在该装备上的合法最高值为10,000：当前值7,800则完成率78%；即使这条词条当前标记为低档，也仍按7,800/10,000计算。若该属性有全身上限，则取该槽可达到的属性上限与当前剩余全身上限中的较小值。
