版本：QC\_EQUIPMENT\_GRADE\_V1\_5。日期：2026-11-02。状态：用户确认采用统一五档品阶方向；本版替代V1.4中蓝/紫/金品质并存的设计。正式数值接入前仍需生成配置与迁移校验。

## 1. 最终统一决定

取消蓝色、紫色、金色作为独立装备品质/稀有度等级。所有新装备只使用一套五档装备品阶：

| EquipmentGrade | 中文品阶 | 随机属性数量 | 设计定位 |
| --- | --- | --- | --- |
| G1 | 普通 | 1—2条 | 入门装备 |
| G2 | 优秀 | 2—3条 | 初级构筑 |
| G3 | 精良 | 3—4条 | 中期成型 |
| G4 | 卓越 | 4—5条 | 高阶构筑 |
| G5 | 传说 | 5—6条 | 终局构筑 |
| 不再出现“蓝色普通”“紫色精良”“金色传说”等双重品质命名。装备只显示一个品阶，例如“传说腰带”。 |  |  |  |

## 2. 三个独立参数

必须明确区分：

1. 装备品阶Grade：决定允许生成的属性条数范围、属性池解锁范围及品阶专属外观。
2. 装备有效等级Le：决定属性数值成长上限。Le沿用V2岛屿入口/末级夹取规则。
3. 当前属性值CurrentValue：决定该属性完成率。<br />品阶不再通过蓝/紫/金系数二次乘算。每个AttributeMax由EquipmentGrade、Le、装备部位、AttributeId和合法最高档配置直接查表或公式计算。

## 3. 属性数量生成概率

装备生成时先确定品阶，再从对应范围抽属性数量。属性数量只抽一次，生成后永久写入装备实例。

| 品阶 | 属性数量 | 概率 |
| --- | --- | --- |
| 普通 | 1条 | 70% |
| 普通 | 2条 | 30% |
| 优秀 | 2条 | 60% |
| 优秀 | 3条 | 40% |
| 精良 | 3条 | 60% |
| 精良 | 4条 | 40% |
| 卓越 | 4条 | 60% |
| 卓越 | 5条 | 40% |
| 传说 | 5条 | 70% |
| 传说 | 6条 | 30% |
| 该表只控制已确定品阶后抽到多少条属性，不代表各品阶掉落概率。八岛掉落、制造、宝箱和商店需要另设EquipmentGrade权重，不能把条数概率当作品阶掉率。 |  |  |

## 4. 属性池与槽位

首期仍使用现有20种普通词条F01—F20，不因取消蓝紫金而删除词条类型。品阶逐级开放属性池：

- 普通：基础属性池F01—F04。
- 优秀：F01—F08。
- 精良：F01—F12。
- 卓越：F01—F16。
- 传说：F01—F20。<br />以上为开放范围；仍必须同时满足部位词池限制。部位不允许的属性不能生成。F01—F04按现有规则可重复；F05—F20同件每种最多一条。若合法属性池不足以填满抽中的数量，重新抽取剩余合法类型；仍不足时按实际条数生成并记录原因，不能造出非法词条。<br />战术铭纹M01—M08仅允许传说装备使用，并且只能占用第3条属性槽；不增加总条数。全身最多启用2枚不同铭纹ID。传说装备第三条可按原V3规则在普通词条与铭纹之间生成/刻印选择；第四至第六条只能使用普通词条。

## 5. 属性上限与数值成长

移除原蓝/紫/金词条系数0.40/0.64/1.00。AttributeMax唯一由以下参数决定：<br />AttributeMax = f(EquipmentGrade, Le, EquipmentSlot, AttributeId, MaxTier, RuleVersion)

- EquipmentGrade：品阶影响该属性的成长档位与可达上限。
- Le：使用该装备所属岛的有效等级，禁止跨岛借用更高岛数值。
- EquipmentSlot：头环、肩甲、护手、护膝、翅膀分别维护合法词池和上限。
- AttributeId：每种属性使用自己的数值单位和最大值。
- MaxTier：统一以该品阶、部位和等级允许的最高合法词条档位作为分母，不使用当前条目自身的低档上限。
- RuleVersion：记录上限公式版本，便于旧装备迁移和评分重算。<br />同一属性的CurrentValue与AttributeMax必须单位一致。固定生命值用生命值；攻击值用攻击值；暴击率用百分点；减伤/抗暴比例用百分点。百分比显示只供UI使用，服务端以权威数值计算。

## 6. 评分公式（1亿封顶）

每件防具最大6条属性，统一分母6：<br />Ratio\_i = clamp(CurrentValue\_i / AttributeMax\_i, 0, 1)<br />EquipmentScore = floor(100000000 × Σ(Ratio\_i) / 6)<br />属性首期等权。没有属性的槽不参与完成率平均，但会因为没有贡献项而自然降低总分。属性条数是评分潜力，属性当前值相对上限的完成率是质量。六条属性全部达到各自上限时为1亿分。

| 有效属性数量 | 每条完成率均为80%时的评分 | 全部满上限时的最高评分 |
| --- | --- | --- |
| 1条 | 13,333,333 | 16,666,666 |
| 2条 | 26,666,666 | 33,333,333 |
| 3条 | 40,000,000 | 50,000,000 |
| 4条 | 53,333,333 | 66,666,666 |
| 5条 | 66,666,666 | 83,333,333 |
| 6条 | 80,000,000 | 100,000,000 |

## 7. 装备品阶与星级评分展示分离

装备品阶是生成时确定的身份；评分星级由当前评分动态决定。品阶为普通、优秀、精良、卓越、传说；评分星级按装备评分动态变化，可随着洗炼提高或降低。

| 装备评分 | 评分星级 |
| --- | --- |
| 0—19,999,999 | ★☆☆☆☆ |
| 20,000,000—39,999,999 | ★★☆☆☆ |
| 40,000,000—59,999,999 | ★★★☆☆ |
| 60,000,000—79,999,999 | ★★★★☆ |
| 80,000,000—100,000,000 | ★★★★★ |
| UI必须分别展示“传说品阶”和“★★★★评分星级”，不能只显示一个星级而让玩家误解品阶变化。 |  |

## 8. 洗炼规则

- 普通洗炼只替换一条属性，属性总条数不变，品阶不变。
- 跨属性替换时读取新属性ID对应的AttributeMax，不沿用旧属性上限。
- 候选生成后显示候选属性数值、完成率、旧评分、新评分与差值。
- 确认替换后原子提交属性并重算评分；取消不改变装备。
- 补充属性若作为新功能开放，必须独立命名、独立成本和独立事务，不得伪装成普通洗炼。

## 9. 旧装备与配置迁移

V2历史蓝/紫/金品质装备不得直接删除、重抽或强制改变属性。迁移采用一次性映射：

- 读取旧实例当前有效随机属性数量。
- 根据条数映射到合法新品阶区间：1条→普通；2条→普通/优秀；3条→优秀/精良；4条→精良/卓越；5条→卓越/传说；6条→传说。
- 在有多个可选品阶时，优先参考旧品质顺序：蓝色映射较低候选、紫色映射中间候选、金色映射较高候选；但不得改变属性数量以迎合映射。
- 记录LegacyQuality、LegacyGrade、MigrationVersion，保留原装备ID、属性值、强化、星铸、制造来源与词条，不重新收费、不重新随机。
- 旧装备原属性若超过新AttributeMax，迁移时保留实际值，评分完成率封顶100%，并标记LegacyCapExceeded；不静默削弱玩家资产。
- 新生成装备不再读取蓝/紫/金字段；旧字段只用于历史存档兼容，后续迁移完成后停止写入。

## 10. 适用范围与当前限制

本品阶与1—6条属性数量规则首期应用于72件防具。V2的32把武器没有随机词条槽，不能为了统一外观而虚构属性；武器仍保留独立动作与性能面板。若未来决定给武器增加随机属性，必须另行定义武器品阶词池、属性数量和上限表。<br />本版替代V1.4中蓝/紫/金品质准入表、品质系数及其与五档装备等级并存的设计；替代V1.4中“蓝/紫/金决定AttributeMax”的规则。V1.3的属性完成率算法、V1.4的五档条数范围与概率继续保留并由本版统一。
